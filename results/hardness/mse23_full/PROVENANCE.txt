1. WHAT THIS IS
------------------------------------------------------------------------------
75 single-record JSONL shards (one per SLURM array task), each profiling one
MaxSAT instance with the RC2 solver under a fixed time budget. Aggregating them
yields the tier stratification used for instance selection downstream.

  Shards        : tasks/mse23_full_arr_task_{1..75}.jsonl   (1 record each)
  Aggregate     : all_results.jsonl, all_results.csv        (built, see §6)
  Summaries     : tier_summary.csv, bench_summary.csv

The shards are the source of truth; the aggregate + summaries are reproducible
build products of analyze_tiers.py.

3. PROFILING RUN
------------------------------------------------------------------------------
  Solver           : RC2 (core-guided MaxSAT, PySAT)  — CPU-bound; no GPU used
  Time budget cap  : cap_s = 600.0 s per instance
  Hard kill margin : subprocess killed at cap + 60.0 s wall
                     (a solve_s of ~660 s means "killed at the margin")
  On non-convergence: best lower bound recovered from the RC2 progress file

  Per-record schema (observed):

4. TIER DEFINITIONS
------------------------------------------------------------------------------
Observable semantics (read from the data):

------------------------------------------------------------------------------
5. CAVEATS THAT SHAPE THE TIERS
------------------------------------------------------------------------------
  - cap_s = 600 s with a +60 s kill margin directly sets the T1/T3 boundary.
    Re-running at a different cap changes which instances land in T3. Any tier
    comparison must hold cap_s fixed (or report it).
  - cost_lower_bound for killed instances is RECOVERED from a progress file, not
    a clean solver return — treat it as a best-effort bound.
  - lb_ratio is only meaningful where a bound was recovered (mainly T3).

------------------------------------------------------------------------------

  python -m src.bench.analyze_tiers \
      --in-dir  results/hardness/mse23_full/tasks \
      --out-dir results/hardness/mse23_full

   bench_summary.csv, and prints the cross-instance report.)

Re-profiling a subset (e.g. bumping cap_s for T3): re-run only those array
tasks, drop the new shards into tasks/, and re-run the command above.
