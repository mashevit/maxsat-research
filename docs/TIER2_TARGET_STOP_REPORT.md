## What changed (staging only — `git status` shows nothing outside `cluster_staging_maxsat/`)

**A — `src/evo/memetic.py`:** `run_memetic(..., target_cost=None)`.
`total_soft_weight` is summed once before the loop in the general weighted form;
the comparison site converts `incumbent_cost = total_soft_weight -
best_soft_weight` and stops on `<=`. Individuals with hard violations are
excluded rather than converted (their fitness is a penalty, not a soft weight).
The incumbent check moved inside the fill loop so it fires after each child's
polish; with `target_cost=None` that is exactly equivalent to the
end-of-generation update (elites can never beat the running best, and strict `>`
preserves the tie-break). Returns `stop_reason` and `time_to_target_s` on all
paths. `memetic.py:93`'s leaked `ind` untouched.

**B — `src/cli/run_memetic_shard.py`:** opt-in `--stop-at-oracle`;
`--oracle-cost` alone still only fills the gap fields. Four additive fields. The
B3 cross-check sets `status="cost_mismatch"` when a target stop fires but the
re-derived `best_cost` exceeds the target.

**C — `scripts/tier2_memetic_array.sbatch`:** `--time=00:20:00`. `GRACE` still
`${GRACE:-60}`; 900 + 60 = 960 s (16 min) leaves ~4 min for `module load`, conda
activation and parsing, and the SIGALRM watchdog caps the process at 960 s
regardless of generation-boundary overrun. `--mem`, `--cpus-per-task`,
`OMP_NUM_THREADS` unchanged. `smoke_tier2_memetic.sbatch` has its own
`--time=00:05:00` and `BUDGET=10`, so it inherits nothing — left alone.

> **Judgement call beyond the literal Task C text:** I added `STOP_AT_ORACLE`
> (default `0`) to the array sbatch. Without it nothing on the cluster can reach
> the new flag. It stays opt-in — `sbatch --export=ALL,STOP_AT_ORACLE=1`.

**D — manifest:** 390 lines, no header, `job_id` on line N is `t2m_<N>` for all
390, single budget `900`, 26 instances × 3 configs × 5 seeds. `tier2_oracle.csv`
and `tier2_skipped.txt` regenerated byte-identical.

**E — `DIVERGENCE.md`** (new) with the amended §2.2 loop (split in two, and for
the two divergent paths `IDENTICAL` is inverted into the failure signal), the
caps-mismatch subsection, and the `combine_tier2.py` note. Pointer added to
`readme.txt`.

## Verification output

The §7 commands as written run from the repo root, where
`src.cli.run_memetic_shard` resolves to the **unmodified repo copy**. I ran them
from the staging root instead — which is what the sbatch does (`cd ..` from
`scripts/`).

```
1. default path      status=ok cost=2 opt=1 wall=9.262 stop=time_cap t_target=None
                     target_cost_used=None stop_at_oracle=False  gens=3 children=171
2. target path       status=ok cost=1 opt=1 wall=8.799 stop=target t_target=8.783
                     budget_s=900.0  target_cost_used=1  is_optimal=True
3. weighted + hard   status=ok cost=8 opt=8 wall=0.278 stop=target t_target=0.265
                     n_hard=100 n_soft=500 soft_total_weight=500
                     best_soft_weight_reported=492.0 unsat_soft_clauses=8 hard_violations=0
                     500 - 492 = 8 == best_cost   (matches §6.3's measured cross-check)
4. error path        FATAL: --stop-at-oracle requires --oracle-cost -- there is no
                     target to stop at without it. ...
                     exit=2, no shard written
```

Two extra checks: target 500 on an instance with optimum 1 stops at
`best_cost=83` (confirms `<=`, not `==`, and the pre-loop check — `t_target=0.0`,
zero generations); and a stubbed `run_memetic` returning a target stop with a bad
assignment yields `status="cost_mismatch"`, exit 1.

`run_ea.py` and `run_experiment.py` were run against both the repo and the
staging `memetic.py` (via `PYTHONPATH`). Identical solutions
(`best_soft_weight=492.0`, `hv=0`, `soft_unsat=8.0`); only `elapsed_sec` and
`total_flips` differ, and `total_flips` varies run-to-run on the **unmodified**
repo copy too (83515 vs 55734 across two identical invocations), since flips are
bounded by per-child wall clock.

**Note on test 1:** `wall_time_s` is 9.26 for an 8 s budget, not ~8 — the cap is
only checked at generation boundaries, so the last generation overruns. That is
pre-existing and unchanged; it's bounded at ~20 s for `memetic_deeppolish`, which
is why the 20-minute limit still holds.
