## 2. GSM8K → Ollama staging pipeline

**Good news: the full chain IS committed as sbatch** — it does not live only on
the cluster. It is just split across two directories.

Train/eval half — `gsm8k_lora_v2_consolidated/`:
- `train.sbatch` → `train.py --quick` (unsloth; base options include
  `unsloth/Qwen2.5-7B-bnb-4bit`, flagged "relevant for MaxSAT")
- `eval.sbatch` → `evaluate.py`
- outputs `./gsm8k_lora_model` (the adapter)

Merge → GGUF → serve half — `cluster_staging/LoRA to Ollama/`:
- `merge.sbatch` → `merge_export.py` : adapter → `./merged_16bit` (HF 16-bit)
- `gguf.sbatch` : `merged_16bit` → GGUF f16 → quantize Q6_K (builds llama.cpp)
- `quantize_f16.sbatch` : recovery/fast path when the f16 GGUF already exists
- `serve.sbatch` : starts Ollama in Apptainer, `ollama create` from `Modelfile`,
  runs `compare_base_vs_lora.py`
- `Modelfile` : `FROM …/merged_16bit-Q6_K.gguf`, GSM8K-specific `TEMPLATE`

**So nothing in the chain is missing as an sbatch.** The real gaps:
1. **No orchestrator.** There is no single sbatch chaining
   train → merge → gguf → serve via `sbatch --dependency=afterok:`. Each stage
   is launched by hand. Suggested add: `cluster_staging/run_lora_pipeline.sbatch`
   (or a `scripts/` launcher) that submits the four jobs with dependencies and
   threads the adapter/merged/gguf paths through.
2. **Two dirs + hardcoded relative paths.** Train writes `./gsm8k_lora_model`
   in `gsm8k_lora_v2_consolidated/`; merge/serve assume `./gsm8k_lora_model`
   and `./merged_16bit` in `cluster_staging/LoRA to Ollama/`. `Modelfile` hard-
   codes `/home/mashevit/gguf_models/…`. Consolidating (or parameterizing via
   env) is needed before this is hands-off.
3. **Dir name has a space** (`LoRA to Ollama/`) — fragile in shell/sbatch.
4. **Everything is GSM8K-templated.** `Modelfile` `TEMPLATE` and the eval path
   reproduce the GSM8K prompt; nothing here is MaxSAT-aware yet (expected — §3).

Ollama serving itself is confirmed working, so this half is validated; only
orchestration/consolidation and the MaxSAT re-template remain.

## 3. MaxSAT LoRA training set (the real fine-tune, not GSM8K)

**Target interface** (`src/llm/advisor.py`, `src/llm/prompt.py`):

- **Input prompt** = exactly `build_prompt(...)`: `n_vars`, count of violated
  hard clauses, up to ~20 violated-hard clause examples (`{"idx","lits"}`),
  `extra` (`gen`, `child_hv`), seed.
- **Target completion** = the strict JSON advice object:
  `{"flip":[...], "set_true":[...], "set_false":[...], "note":"..."}`
  consumed by `apply_advice` (a small ≤~10-var edit toward fewer violations).

**Where supervision comes from (recommended hybrid):**

1. **Input distribution ← `memetic_ea` traces.** Instrument `run_memetic` to
   dump the real per-child states it already produces (`child_bits`,
   `violated_hard_idxs`, clause examples). These are realistic, on-distribution
   inputs the served model will actually see. *Requires implementing the
   currently-stubbed `violated_idxs` first.*
2. **Gold labels ← RC2 oracle (T1/T2 only).** `src/cli/run_opt_rc2.py` returns
   `rc2.model` — the full optimal assignment (`--model-out`/`--print-model`).
   For a child, the gold edit = the variables where the child disagrees with the
   RC2 model, restricted to variables occurring in the violated hard clauses.
   That yields ground-truth `set_true`/`set_false`/`flip` lists. Clean and
   cheap — but only where RC2 has an optimum (so **not T3**).
3. **Distillation from a larger model ← complement, not the primary generator.**
   Use a stronger model on the same `build_prompt` with rejection sampling
   (keep advice that, after `apply_advice` + `short_polish`, lowers
   hard-violations / soft cost) for: (a) T3, where no optimum exists, and
   (b) populating natural-language `note` reasoning. The oracle is the better
   labeler wherever it is available; distillation fills the T3 gap.

**Verdict:** an LLM batch/distillation job is the right generator *only for the
T3 slice and for reasoning traces*. For T1/T2 the RC2 oracle gives exact labels
for free — prefer it.

**What the repo needs to support this:**
- Implement `violated_idxs` in `memetic.py` (currently `[]`) and add a child-
  state dump path (collector) emitting prompt-features per child.
- A dataset builder joining dumped child states with RC2 models (batch
  `--model-out`; `batch_opt_rc2.py` currently does not export models) → emits
  `{prompt, completion}` JSONL in the exact advisor format.
- Decide the single `best_cost` semantic (HARNESS_PLAN §5 Q1) before labeling.
- Adapt the unsloth kit: `train.py` is hardcoded to
  `load_dataset("openai/gsm8k")` + `format_example` + `utils.build_prompt`.
  Add a `--dataset <jsonl>` loader and a MaxSAT `build_prompt`/`build_completion`
  pair, and replace the GSM8K `Modelfile` `TEMPLATE` with the advisor template.
